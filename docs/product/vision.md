# 产品愿景

## 一句话

一个通用的多租户数据采集平台：每个"实例"（一个采集项目）里，模板设计人用 Excel 设计采集模板并发布给机构，机构用户在浏览器里填报并提交，数据以带类型的结构化形式沉淀，供之后的审批和输出使用。

## 现状与为什么要从零重建

- 早期原型想做同样的事，但**从未上线**。
- 它在数据库设计、架构、技术栈、角色权限和代码质量上都有严重问题，用户决定不改造，只提取"它想达成什么"，从零重建。
- 新系统要**通用**：不再写死某一行业字段，也不再绑定某一个部门。

## 目标用户

| 角色 | 是谁 | 现在怎么解决这个问题 | 痛点 |
|---|---|---|---|
| 平台管理员 | 运营平台的人，管理所有实例 | 无（早期原型未上线） | 需要创建实例、指派实例管理员，不能看到实例内的业务数据以外的东西 |
| 实例管理员 | 一个采集项目的负责人 | 无 | 要管理本实例的科目表、机构、用户、角色 |
| 模板设计人 | 设计采集表格的人 | 用 Excel 手工做表，靠加载项插入属性和分类 | 科目表和模板脱节，科目一变模板就对不上；制作慢 |
| 填报人 | 机构里负责填数据的人 | 收到 Excel 邮件，填完回传 | 格式错误和公式错误要到事后才发现，反复返工 |
| 机构管理者 | 机构里管理本机构用户的人（待确认，见 Q-016） | 无 | 无法自己管本机构的人 |
| 数据使用方（第二期） | 要看汇总结果的人 | 无 | 第一期不做 |

## 成功标准

以下指标由 AI 建议、用户默认，**基线数字尚未测量（Q-007）**，量化目标待基线出来后修正。

- 第一期验收：在本地环境，用一个种子实例完整跑通一轮"建 COA → 设计模板 → 发布 → 多机构填报 → 提交 → 撤回重提"，无阻断缺陷。
- 模板制作时间：比现状缩短 50% 以上（基线：现在做一个模板要多久，待测）。
- 数据质量：提交前被系统校验拦截的格式和公式错误占全部此类错误的 90% 以上；因数据错误导致的返工次数比现状减少一半（基线待测）。
- 按期完成率：截止日前完成提交的机构比例，比现状提高（基线待测）。
- 稳定性：第一期没有数据丢失；任何数据变更都能在审计日志里追溯。

## 范围

### 第一期（对应 REQ 编号）

分两个里程碑：

**1a 地基与模板**：实例与授权（REQ-001 到 REQ-004）、机构（REQ-005、REQ-006）、财年与报告期（REQ-007）、科目表（REQ-008 到 REQ-013）、Excel 加载项与模板（REQ-014 到 REQ-018）、审计（REQ-019）。

**1b 填报**：REQ-020 到 REQ-028。

**贯穿全程**：多语言、无障碍、安全与隐私、本地运行、数据留存（REQ-029 到 REQ-033）。

### 以后再做

- **第二期：审批流程**（REQ-034）：审核、批准、驳回、重提的状态机。*需要预留*：提交快照结构要能挂上审批记录；填报状态机留出扩展点。
- **第二期：数据输出**（REQ-035）：汇总报表、Insights、仪表盘、合并报表。*需要预留*：单元格值必须是带类型的结构化数据，并和 COA 版本绑定，否则报表口径会漂移。
- **第三期：离线 Excel 填报**（REQ-036）。*需要预留*：模板结构要能导出成带映射的 Excel。
- **第三期：站内消息**（REQ-037）、**主题与个性化设置**（REQ-038）。

### 明确不做（第一期）

- 单元格级实时协同编辑：只做工作表级锁。风险高，收益小。
- 审批、报表、仪表盘：见上。
- 生产云部署：第一期只在本地环境运行。
- 迁移早期原型数据：早期原型从未上线，无生产数据（待确认，见 Q-019）；COA、机构、用户用 Excel 批量导入。
- 通用的"逻辑删除"标志：按数据性质分别处理，见 REQ-012。

## 约束

| 类别 | 要求 | 来源 |
|---|---|---|
| 规模 | 目标：几千个机构、几万用户；截止日前后峰值并发按全部用户的 5% 到 10% 估算 | 用户回答（量级）；峰值比例为 AI 建议，待用户确认 |
| 性能 | 打开一份典型模板 3 秒内可编辑；单次保存和校验 500 毫秒内返回（典型指"一个工作表、数千个单元格"，具体见 Q-017） | AI 建议，待用户确认 |
| 可用性 | 第一期本地运行，无可用性要求；上线前再定 | 用户回答 |
| 部署环境 | 第一期仅本地（docker compose 一条命令启动）；上线目标未定（Q-002），设计上与云无关 | 用户回答 |
| 预算 | 未提供；原则：尽量不依赖多套商业组件授权（早期原型同时用了两套） | AI 建议，待用户确认 |
| 合规 | 无障碍 WCAG 2.1 AA；英法双语；数据驻留；上线前做隐私影响评估与威胁风险评估 | 用户回答 |
| 时间 | 未提供 | — |
| 维护 | AI（Claude Code）开发和维护，用户是产品负责人和验收人。因此要求：单体加一个数据库，分层由工具强制检查，测试和文档完整 | 用户回答 |

## 假设

- 设计人都有支持 Office 加载项的桌面版 Excel。验证：向设计人确认版本；不支持则退到"下载模板上传"。
- 早期原型的模板结构（工作表是"Tab"，列是属性，行是分类，交叉点是录入位）有代表性。验证：让用户提供真实模板样例（老仓库 `OfflineTool/GDCS_Template.zip`），并做 /spike。
- 浏览器里的电子表格组件能同时满足无障碍、公式和性能要求。验证：/spike（Q-008）。
- 早期原型没有需要迁移的生产数据。验证：问用户（Q-019）。
