# ADR-0010 交付与环境：本地加 CI，代码放 GitHub，线上环境推迟

- 状态：已接受（含需要确认的合规事项，见"后果"）
- 日期：2026-10-30
- 相关需求：REQ-031、032；Q-002、Q-025、Q-026

## 背景

第一期只在本地运行（用户确认）。上线平台未定（Q-002），且要求数据驻留。规范库的部署说明默认针对 GitHub 和商业托管平台（Vercel、Render 等）。这是个人项目，线上平台和区域由作者以后决定。

## 候选方案

代码托管：

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| GitHub 仓库（私有或公开） | 工作流（/scaffold、/roadmap、/implement）直接使用其 issues、PR、Actions | 免费版的私有仓库没有分支规则和必须通过的检查；公开仓库代码对所有人可见 | 能走完整工作流 |
| 仅本机 git | 不必决定托管 | issues、PR、自动审查不可用 | 暂时的 |

环境：

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| 只有本地 + CI | 最少；不必预设平台和区域 | 无线上验收环境，靠本机演示 | 第一期只在本地运行 |
| 再加 PR 预览、测试环境 | 方便验收 | 需要先选平台和区域；现在选会预设答案 | 平台已定 |

## 决策

- **代码托管：GitHub 公开仓库**（用户选择）。私有仓库在免费版上不能用分支规则，所以改为公开，作为个人项目。
- **环境：本地 + CI 自动检查**（用户选择）。不建任何线上环境，不配部署流水线；上线平台定了（Q-002）再配。
- **本地容器环境：Rancher Desktop**（Apache-2.0，WSL2，dockerd 引擎，不启用 Kubernetes），由用户在本机安装（Q-028）；不用 Docker Desktop，因为大型组织需要付费订阅，与"偏好免费"冲突。本机安装前，用 Keycloak 解压版、本机 PostgreSQL 和 Node 原生运行作为备选（ADR-0006 的探针已证明 Keycloak 可以这样跑）。
- **本地**：`infra/docker-compose.yml` 一条命令启动 Caddy、两个 API 实例、一个 worker、PostgreSQL、Keycloak、Mailpit，带种子实例和演示数据。本地 HTTPS 用 mkcert（MIT）生成受信任的证书（Office 加载项要求 HTTPS）。
- **CI（GitHub Actions）**：格式、lint、架构检查、类型检查、单元与组件测试、构建、Storybook 构建与无障碍检查、Playwright 端到端 + axe + 视觉回归（用同一份编排起整套系统）、密钥扫描（含历史）、重复代码检查。
- **分支策略**：由 /setup-ai-review 时确定（建议 GitHub Flow，单人维护）。
- **镜像**：每个组件有 Dockerfile，镜像以提交号和版本号打标签，为将来回滚（重新部署旧标签）做好准备；暂不推送到任何线上仓库。

## 证据

无探针。

## 后果

- 好处：第一期没有线上成本，也没有对平台和区域的预设；一份编排同时服务本地和 CI。
- 代价：没有线上验收环境，用户验收靠在本机点开看；没有 PR 预览；上线前要补部署流水线、线上密钥库、备份与监控。
- 仓库公开：代码、文档和提交历史对所有人可见；不得提交密钥和个人数据（CI 有密钥扫描）。
- 什么时候应该重新考虑：Q-002 定了线上平台；需要给相关方一个可访问的验收地址；GitHub 不被允许。
