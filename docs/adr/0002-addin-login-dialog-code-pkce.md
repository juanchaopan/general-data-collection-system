# ADR-0002 Excel 加载项的登录方式

- 状态：已接受（含必须补齐的验证，见"后果"）
- 日期：2026-10-30
- 相关需求：REQ-014、REQ-002；Q-001、Q-011、Q-012

## 背景

模板设计人用 Excel 加载项直接从当前实例的科目表里选属性和分类（REQ-014），所以加载项必须登录平台并带着令牌调用受保护的 API。

约束：
- 第一期只在本地运行，用户是本地账号；上线后用什么身份提供者（IdP）未定（Q-001）。
- 用户偏好免费方案。
- 令牌不能写进工作簿或持久存储（REQ-014、REQ-031）。
- 登录过期不能丢设计人在工作簿里已做的内容（REQ-014 验收 6）。

## 候选方案

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| A. Office SSO（`Office.auth.getAccessToken`） | 无感登录 | 需要 Entra ID 应用注册和 Microsoft 365 账号；本地账号会报 13003；官方文档建议始终提供对话框回退（来自文档，未实测） | 已经用 Entra ID |
| B. 对话框 + OAuth2 授权码 + PKCE，平台自己做授权服务器 | 与 IdP 无关，本地账号和以后的 Entra 都能用；只用标准协议，零授权费 | 平台要实现授权端点；要处理跨域与对话框首页同域的要求 | 身份提供者未定、要免费 |
| C. 设备码流程 | 不依赖对话框 | 用户体验差；未研究 | 对话框被策略拦截 |

## 决策

采用方案 B：平台提供 OAuth2 授权码 + PKCE 端点；加载项用 `displayDialogAsync` 打开平台登录页，回调页用 `messageParent` 把授权码交回任务窗格，任务窗格用 PKCE 换令牌。

- 重定向地址只接受白名单；授权码一次性使用，错误的 verifier 也会烧掉该码。
- 访问令牌短期有效，刷新令牌每次使用都轮换（旧的立即作废）。
- 令牌只放内存，不写工作簿、`localStorage`、`sessionStorage`、文档设置。
- 过期后用刷新令牌静默续期，不要求重新输入密码，工作簿内容不受影响。
- 上线接入 Entra ID 时，把 Entra 放在平台授权服务器之前（身份提供者可插拔，REQ-002），加载项不用改；Office SSO 可以以后作为可选的无感登录加上，不作为基线。
- 判据 S1 到 S4（协议正确、Excel 内端到端、令牌不落盘、过期续期不丢内容）经用户确认（2026-10-30）。

## 证据

探针代码用完即弃，未保留在本仓库。完整记录见 `assets/spike-addin-auth-SPIKE.md`。

| 判据 | 结果 |
|---|---|
| S1 协议层 | 12/12 通过：错误密码、白名单外的 redirect、错误 verifier 被拒；授权码一次性；无令牌和过期令牌返回 401；刷新令牌无需密码续期并轮换 |
| S2 Excel 端到端 | 通过：Windows 桌面版 Excel 16（Microsoft 365）里，窗格 → 对话框 → 授权码 → 换令牌 → 调用 API 返回 200 |
| S3 令牌不落盘 | 通过：`storage_audit` 在检查的存储位置里没找到令牌 |
| S4 过期续期 | 通过：令牌 15 秒过期后无需密码续期，`A1_unchanged: true` |
| 对话框是否被公司策略拦截 | 没有拦截 |

局限：
- 登录是探针自动提交的（从授权页打开到提交只隔约 76 毫秒），没有真人输入账号密码，所以对话框的真人体验、输错密码的提示都没测。
- 同源部署；跨域（CORS、对话框首页与窗格同域）没测。
- 只测了 Windows 桌面版 Excel；Mac 和网页版没测。
- 没有真实 Entra ID，没测 Office SSO 或嵌套应用认证。
- 本机"商店类加载项"被策略关闭（`disableomexcatalogs=1`），开发者侧载可用。

## 后果

- 好处：免费；与 IdP 无关，Q-001 不用先定；协议是标准的，有成熟的客户端和安全指南可对照。
- 代价：平台要自己实现并长期维护一个授权服务器（授权、令牌、刷新、撤销、日志）；这是安全敏感代码，要有测试和评审。
- **必须在 REQ-014 验收前完成的验证**（Q-022）：
  1. 真人在对话框里登录，包括输错密码、窗口位置、关闭对话框。
  2. 跨域部署：加载项页面与 API 不同源时的 CORS 配置，对话框首页与窗格同域的约束。
  3. Mac 和网页版 Excel（若设计人会用到）。
  4. 向 IT 确认加载项的分发方式（Q-012）：本机策略关闭了应用商店类加载项，最终用户大概率需要集中部署。
- 什么时候应该重新考虑：公司策略以后拦截 Office 对话框；平台决定只用 Entra ID 且设计人都是 Microsoft 365 工作账号（那时 Office SSO 更省事）；加载项要支持不能弹对话框的环境。
