# ADR-0007 通信：REST + OpenAPI（zod），实时用 SSE，幂等与错误约定

- 状态：已接受
- 日期：2026-10-30
- 相关需求：REQ-014、018、023、024、027

## 背景

三类调用方：Web 应用、Excel 加载项、以后可能的其他工具。需要：稳定的接口契约；前后端和加载项共用校验结构；工作表锁状态和发布进度要实时推送；提交、发布、导入要幂等。

## 候选方案

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| REST + OpenAPI，zod 定义结构，锁用心跳轮询 | 标准；简单；好测 | 状态更新靠轮询，略慢 | 实时性要求不高 |
| REST + OpenAPI + SSE 推送（用户选择） | 锁状态和进度实时；单向推送比 WebSocket 简单 | 长连接占服务器资源；代理和负载均衡要配置超时；需要 HTTP/2；多实例要转发 | 需要实时反馈 |
| tRPC | 端到端类型安全 | 不是标准接口，Excel 加载项和其他工具集成不便，没有 OpenAPI | 全 TypeScript 且无外部调用方 |
| GraphQL | 灵活查询 | 复杂度高，缓存和授权更难 | 复杂的查询组合 |

## 决策

- **REST + OpenAPI**：路径 `/api/v1/...`；结构用 `libs/schemas` 里的 zod 定义，前端、后端、加载项共用，并由它生成 OpenAPI。
- **SSE**（用户选择）：`GET /api/v1/events` 推送工作表锁变更和发布进度。
  - 必须走 HTTP/2（避免浏览器对同一域名的 6 条连接上限）。
  - 服务端定期发送注释心跳，代理的空闲超时要大于心跳间隔。
  - 多 API 实例之间用 PostgreSQL `LISTEN/NOTIFY` 转发事件。
  - 浏览器检测到断开退回轮询；轮询是兜底，所有状态也能通过普通 GET 获得。
  - 事件只带"变了什么"，前端收到后重新取数据，事件里不带敏感内容。
- **工作表锁**：获取、续期（心跳，30 秒）、释放都是普通 REST；锁令牌随每次保存提交；服务端校验。
- **幂等**：提交、发布、导入要求 `Idempotency-Key`；单元格保存带变更编号，重复送达不重复写审计。
- **错误**：RFC 7807 `application/problem+json`，带稳定的错误码；前端按错误码本地化，不依赖服务端消息文字。
- **请求编号**：代理生成 `x-request-id`，贯穿日志和任务。
- **版本**：路径版本；新旧并存期间不删旧字段。
- **认证**：`Authorization: Bearer`；跨域被避免——所有入口同一域名（ADR-0006）。

## 证据

无探针。SSE 与 `LISTEN/NOTIFY` 的多实例转发和代理超时需要在本地多实例环境里验证（纳入 1b 的早期测试）。

## 后果

- 好处：契约清晰、可测；一份 zod 结构三处共用；加载项与网页端同一套接口。
- 代价：SSE 的运维细节（超时、HTTP/2、断线重连）要处理；`LISTEN/NOTIFY` 需要不经连接池的专用连接；事件丢失要靠重新取数据兜底。
- 什么时候应该重新考虑：连接数使 SSE 成为瓶颈（改轮询或专用推送服务）；需要双向实时协同（那是单元格级协同，需要重新设计）。
