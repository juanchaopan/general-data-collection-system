# SPIKE: Keycloak 能否承担 ADR-0006 对它的要求（Q-027）

**不合并。** 探针代码只为回答问题；结论见 `docs/adr/`。

分支 `spike/keycloak`。判据 K1 到 K5 经用户确认（2026-10-30）。

## 问题

ADR-0006 选了 Keycloak 做身份服务，但它在本项目里没有验证过。它能不能：与 Excel 加载项的对话框配合完成授权码 + PKCE 登录并续期；提供英法双语且无障碍的登录页；通过管理接口创建用户并在失败后恢复；资源占用可接受；自己停掉后 API 仍能校验已签发的令牌？

## 判据

| 编号 | 要验证什么 | 通过条件 |
|---|---|---|
| K1 | 在 Excel 里：加载项对话框 → Keycloak 登录页（真人输入账号密码）→ 授权码 + PKCE 换令牌 → 调用受保护的 API | 窗格、对话框、令牌、API 返回 200 全部走通；重定向白名单外的地址被拒；全程同一个域名（登录页经 `/auth/` 路径） |
| K2 | 刷新令牌轮换；令牌过期后无需密码续期；旧刷新令牌作废；工作簿 A1 的内容不丢 | 与 ADR-0002 探针的 S4 同标准 |
| K3 | 登录页英法双语切换；axe 自动检查；连续输错密码后锁定 | 两种语言下严重和重要违规均为 0；超过阈值后锁定 |
| K4 | 用管理接口创建用户并触发"设置密码"邮件；模拟中途失败后重试 | 重复创建不出现半成品用户；应用能识别已存在的用户并补全；Keycloak 不可用时失败可重试 |
| K5 | 资源占用与启动时间；Keycloak 停掉后，已签发的访问令牌仍能被 API 校验 | 记录内存和启动时间；停掉后令牌在有效期内仍可校验 |

## 时间盒

半天；Excel 集成最多 3 次尝试。到时仍没结论，本身就是结论。

## 不管的事

高可用（多实例）、联合 Entra ID、多因素的体验、登录页美化和完整主题、生产加固、读屏软件真人测试、容器方式运行（本机没有 Docker，Keycloak 用解压版加本机 JDK 21，见"环境"）。

## 环境

- Windows 11 企业版，托管设备；Excel 16（Microsoft 365）；Node 24；Keycloak 26.8.1 解压版（官方 SHA-1 已核对，未验证 GPG 签名），`kc.bat` 使用本机 JDK 21.0.10；浏览器自动化用 ungoogled-chromium 149。
- 用 `start-dev` 模式和内置数据库，**不代表生产配置**。
- 反向代理是探针里一个很小的 Node HTTPS 服务（`server.mjs`），用来验证"单一域名、`/auth/` 转发给 Keycloak"这个设计；生产用 Caddy。

## 怎么运行

见各脚本顶部注释。顺序：导出开发证书 → `start-kc.ps1` → `node smtp-sink.mjs` → `node server.mjs` → `node run-protocol.mjs`（K2、K3，部分 K1）→ 在 Excel 里点加载项（K1）→ `node k4-admin.mjs`、`node k5-resilience.mjs`。账号密码每次运行随机生成，放在临时目录，不入库。

## 结果

### 总表

| 判据 | 结果 | 证据 |
|---|---|---|
| K1 Excel 内登录 | **通过**（有保留，见下） | 真人在 Keycloak 登录页输入账号密码（对话框打开到 `signed_in` 约 25 秒）；窗格、对话框、授权码 + PKCE、API 200 走通；重定向白名单外被拒；`plain` 和无 PKCE 被拒；全程同一个域名（`/auth/` 经代理）；服务端日志的 `PANE>` 行 |
| K2 续期与轮换 | **通过** | 窗格内：令牌过期 → 401 → 刷新（无需密码）→ 200；刷新令牌已轮换；旧刷新令牌复用返回 400；A1 内容未变；`storage_audit` 未在存储中找到令牌。协议脚本 `results-protocol.json` 同样通过 |
| K3 登录页 | **通过**（有保留） | 英法两种语言 axe（wcag2a/2aa/21a/21aa）严重和重要违规均为 0（含"忘记密码"页）；法语页确实是法语；连续输错在第 5 次锁定，锁定后正确密码也被拒，页面不暴露账号已锁定（`results-lockout.json`）；截图 `shot-login-en.png`、`shot-login-fr.png` |
| K4 管理接口创建用户 | **通过** | 创建用户并发"设置密码"邮件；邮件随用户 `locale` 属性变成法语；重复创建幂等（409 后按邮箱查回同一用户）；并发创建同一邮箱只留一个；同邮箱的第二个账号被拒（409）；Keycloak 不可达时干净失败，之后重试成功且无残留；批量创建 200 个用户 0.5 秒（约 430 个/秒，推算 1 万个不到半分钟）（`results-k4.json`） |
| K5 资源与停机 | **通过** | 见下 |

### K5 细节

| 项 | 结果 |
|---|---|
| 首次启动（含建库、导入领域） | 36.7 秒 |
| 重启 | 10.3 秒 |
| 内存（Java 工作集，dev 模式，内置数据库） | 启动后约 460 到 480 MB；运行 19 分钟、跑完全部测试后约 374 MB 工作集、666 MB 私有内存 |
| Keycloak 停机时 | API 仍接受已签发的令牌（公钥已缓存）；陌生密钥签发的令牌 9 毫秒内被 401；登录页和刷新经代理在几毫秒内返回 502；管理接口 3 毫秒内连接被拒（`results-k5-during.json`） |
| Keycloak 重启后 | 领域设置保留；**重启前签发的刷新令牌仍然可用**（会话被保留）；重新登录成功；用户创建重试成功（`results-k5-after.json`） |

### 对设计的影响（探针中发现的）

1. **API 冷启动要预取公钥并重试。** 停机时能验令牌，是因为 API 进程里已缓存了公钥。如果 API 恰在 Keycloak 宕机时重启，冷缓存取不到公钥，就验不了任何令牌。设计上要在启动时重试预取，或把公钥持久化。本探针只证明了"缓存还在时"可用。
2. **刷新令牌必须"单飞"。** 重放一个已使用的刷新令牌，Keycloak 会撤销整条链（重放后最新的刷新令牌也失效，`newestStillWorks: false`）。这是好的安全特性，但如果网页端多个标签页或加载项同时刷新，会把用户登出。客户端要保证同一时刻只发一次刷新。
3. **访问令牌里带了邮箱和姓名。** 个人信息进了令牌，隐私评估角度应通过客户端范围去掉不必要的声明。本探针没做。
4. **同域代理的配置**：`--hostname=https://<域名>/auth`、`--http-relative-path=/auth`、`--proxy-headers=xforwarded`。发现文档仍然宣告支持 `plain`，但给客户端设置 `pkce.code.challenge.method=S256` 后，`plain` 和无 PKCE 都被拒绝。
5. **锁定行为**：第 5 次输错锁定；另有一套"快速重试"保护，失败间隔小于 1 秒会提前锁 60 秒；页面不暴露锁定。
6. **本机没有 Docker，WSL 也没启用。** Keycloak 用解压版加本机 JDK 21 成功运行，所以"不用容器"是可行的备选；但 REQ-032 里"一条 docker compose 命令"的前提在这台机器上不成立（新增 Q-028）。
7. 登录页是 Keycloak 默认主题（`keycloak.v2`），没有定制。

### 没有验证的（保留意见）

- **键盘登录**：用户没有回答"只用 Tab 和 Enter 能否在对话框里完成登录"，记为未验证。axe 的自动检查不代替它。
- **无障碍的自动检查不完整**：axe 对 `color-contrast` 和 `aria-valid-attr-value` 返回"无法判断"（`incomplete`），需要人工或带真实主题时复核。**读屏软件没测。** 所以 K3 的"无障碍"只能算"自动检查未发现严重问题"。
- 只测了 Windows 桌面版 Excel（Microsoft 365）；Mac 和网页版没测。
- 反向代理是探针里的 Node 小服务，不是 Caddy；多实例、高可用、联合 Entra、多因素都没测。
- 邮件只检查了收件人和主题；**没有点击邮件里的链接去设置密码**，也没检查正文。
- 用的是 `start-dev` 模式和内置数据库，**不代表生产配置**；内存和启动时间在生产模式、外部 PostgreSQL 下会不同。
- 第一次运行时的一个"账号锁定"检查写得有缺陷（连续失败间隔太短触发了另一套 60 秒保护，并且当时查询到的锁定状态为空，原因我没有完全查清），已从脚本中移除，改用间隔 1.3 秒的独立脚本重测并通过。
- 登录对话框的显示正常（用户确认），没有弹出安全警告（用户确认）。

### 判断（待用户拍板）

**方向可行，建议采用**：ADR-0006 对 Keycloak 的几项要求，在本机实测中全部满足。保留意见主要在无障碍的人工验证、键盘登录、冷启动取公钥、以及容器环境这几项，它们不改变选择，但要在 /scaffold 和第一个里程碑里落实。
