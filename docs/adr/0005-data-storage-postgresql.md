# ADR-0005 数据存储：PostgreSQL 为唯一数据存储，含队列、文件、租户隔离与分区

- 状态：已接受
- 日期：2026-10-30
- 相关需求：REQ-001、012、013、018、019、027、033；ADR-0003

## 背景

指标：几千机构，一轮 1500 万个单元格值，审计几千万行；单元格保存与审计同事务；多租户隔离；数据驻留；偏好免费；运维少；早期原型数据库设计问题多（通用 `Status`、全文本的值、自引用外键）。

## 候选方案

主数据库：

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| PostgreSQL | 免费开源；分区表、JSONB、行级安全、LISTEN/NOTIFY；托管版在各主要区域都有 | 自建要管备份 | 本项目 |
| SQL Server | 早期原型在用 | 生产需付费授权，Express 版限制 10GB | 已有授权 |
| MySQL / MariaDB | 免费、成熟 | 分区、JSON、行级安全都弱于 PostgreSQL | 无特别理由 |

后台任务队列：

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| pg-boss（存在 PostgreSQL 里） | 无新组件；任务与业务数据同事务；重试、定时、死信；定时任务只跑一次 | 吞吐不如专用队列 | 任务量几万到几十万 |
| Redis（或 Valkey）+ BullMQ | 吞吐高 | 多一个有状态组件；任务与数据不同事务，要发件箱；Redis 许可证有变化 | 任务量巨大 |

文件存储：

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| PostgreSQL，前面套文件存储接口 | 无新组件；同事务、同备份 | 文件大了会让备份变大 | 文件小（模板几 MB，导入导出是单机构数据） |
| Azure Blob + Azurite | 与早期原型一致 | 多一个组件；上线若不是 Azure 要重写 | 上线是 Azure |
| S3 兼容 + MinIO | 可移植 | 多一个组件 | 上线是 AWS 或自建 |

## 决策

1. **主数据库：PostgreSQL**，所有业务数据、审计、任务队列、文件都在其中；Keycloak 使用同一服务器上的独立数据库。
2. **任务队列：pg-boss**。用户先选了 Redis + BullMQ，了解到需要发件箱和多一个组件后，回退到 PostgreSQL 方案。
3. **文件：存 PostgreSQL**，业务代码只依赖一个小的文件存储接口（存、取、删、临时下载）；以后加 Azure Blob 或 S3 适配器，约一百行，业务代码不改。
4. **没有通用的逻辑删除标志**，各对象有明确生命周期（REQ-012）。
5. **租户隔离**：所有租户表有 `instance_id`；代码里过滤，**同时**启用行级安全：每个事务开头 `SET LOCAL app.instance_id`，策略拒绝越界读写；留存清理、平台管理等作业使用单独的数据库角色。（用户确认）
6. **分区**：
   - 单元格值表按 `submission_id` 哈希分区（一开始就做，事后改分区代价高），主键 (submission_id, data_point_id)，行要窄，值用带类型的列（数值、文本、日期；选项存编码）。
   - 审计表按月范围分区、只追加；留存清理时各实例留存期不同，先按实例删行，整月都过期再删分区。
   - 提交快照：提交时把当前行复制到快照表（同结构、不可变），第二期的审批和输出基于它。
7. **多语言名称**：科目表、模板标题、选项标签等存 JSONB `{en, fr}`，并有约束保证必填语言。
8. **时间**：全部 `timestamptz`（UTC）。
9. **迁移**：手写 SQL 迁移文件（分区、行级安全、约束都要手写 SQL），随应用部署；先加后删，兼容上一版本代码。
10. **实时通知**：锁和进度变更用 `LISTEN/NOTIFY` 在 API 实例之间转发（需要一条不经过连接池的专用连接）。

## 证据

无探针。第 6 点的容量依据是 AI 估算（见架构总览的指标）；服务端保存的吞吐需要压测（Q-024）。

## 后果

- 好处：一个数据库、一份备份、一套事务；零授权费；租户隔离有数据库兜底，对隐私评估有力；审计与数据同事务不会不一致。
- 代价：
  - 行级安全要求每个事务设置租户上下文，连接池和测试要配合；策略本身要有测试。
  - 写入压力集中在一个数据库：峰值约 300 次保存/秒，每次若干单元格加审计，需要压测确认（Q-024）。
  - 审计表增长快，留存清理的实现要谨慎（Q-003）。
  - 文件存数据库会增大备份。
- 什么时候应该重新考虑：单元格写入超过单库承受能力（再考虑读写分离或按实例分库）；文件总量超过几十 GB（换对象存储）；pg-boss 吞吐不够；上线平台只提供其他数据库。
